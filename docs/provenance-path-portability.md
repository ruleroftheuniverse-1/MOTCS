# Provenance path portability

This document certifies the path-identity rules used by the Run 018 control-infrastructure release. It is model-independent and is not a Rodriguez replication result.

## Corrected Run 010 root cause

Two portability domains are separate:

- Checkout-byte portability: the root `.gitattributes` file establishes LF bytes for tracked text in supported checkouts. Raw artifact SHA-256 therefore sees the same canonical text bytes on Windows and Linux. This normalization remains necessary for release-artifact byte hashes.
- Provenance-path portability: Run 010 originally serialized repository-relative paths with the host separator. The recorded dependency content hashes already matched LF bytes, but `configs\...` and `configs/...` produced different canonical JSON and therefore different cache keys.

The Run 010 mismatch was caused by path serialization, not by source or configuration content. The accepted source list now uses `path.relative_to(repo_root).as_posix()`. The migration changed the two JSON metadata records only; both NPZ files and every contained array remained unchanged.

The earlier `RUN_018_CI_CACHE_PROVENANCE_REFINEMENT_REQUIRED` decision remains in the migration ledger. It was the honest result because the requested line-ending-only diagnosis was unsupported by the recorded hashes; it was not an implementation-failure verdict.

## Canonical repository dependency path

A repository dependency path is serialized as one repository-root-relative POSIX string:

- `/` separators only;
- no drive letter or leading slash;
- no `.` or `..` segment;
- no checkout-specific prefix;
- no symlink-dependent `resolve()` or realpath expansion;
- original path-segment case is preserved;
- Unicode follows the existing canonical JSON behavior (`ensure_ascii=False` where that schema already uses it).

Absolute paths are accepted by the canonicalizer only as input with an explicitly supplied matching repository root. They are never emitted. These inputs all identify `src/mgf_mot/example.py`:

```text
C:\MOTCS\src\mgf_mot\example.py        root C:\MOTCS
C:/MOTCS/src/mgf_mot/example.py         root C:/MOTCS
/home/runner/work/MOTCS/MOTCS/src/mgf_mot/example.py
                                         root /home/runner/work/MOTCS/MOTCS
src/mgf_mot/example.py                  already relative
```

The canonicalizer fails closed for absolute paths without a root, outside-repository paths, UNC paths, empty paths, drive-relative paths, repeated separators, and explicit `.` or `..` segments. It parses both Windows and POSIX syntax itself rather than delegating meaning to the host `Path` implementation.

## Identity domains

The project does not conflate these identities:

| Domain | Identity rule |
|---|---|
| Artifact byte integrity | Raw SHA-256 of canonical checked-out or generated bytes |
| Structured semantic identity | Schema-specific canonical JSON |
| Repository dependency path | Repository-relative POSIX string inside semantic provenance |
| External source reference | Explicit opaque identifier, citation, or URI; never coerced into a repository path |

## Provenance-bearing object audit

| Subsystem | Path-bearing field | Classification and identity boundary |
|---|---|---|
| Run 010 force-field provenance | `source_hashes[*][0]` | Already repository-relative POSIX; part of the portable cache identity |
| Molecular-model package | member names and source references | Member identities are portable; source references are intentionally opaque |
| Run 012 validation output | displayed package locator | Nonsemantic, platform-local audit display |
| Policy ABI v2 | `source_configuration_paths` | Historical checkout locator; excluded from portable `policy_specification`; included only in explicitly platform-local `full_policy_package` snapshots |
| Open-loop families | `provenance.source_path` | Historical checkout locator; excluded from portable `family_specification`; included only in explicitly platform-local `complete_policy_package` snapshots |
| Apparatus profiles | `source_path_or_citation` | Intentionally opaque external or fixture reference |
| Feedback specs | `source_path_or_citation` | Intentionally opaque external or fixture reference; accepted fixtures use null |
| Experiment checkpoint | `artifact_hashes` keys | Relative to the experiment output root; explicitly platform-local runtime checkpoint identity |
| Author-model intake | `source_base`, `quarantine_directory` | Nonsemantic execution locators; file and bundle hashes carry content identity |
| Release manifest and artifact catalog | catalog paths, protected paths, documentation index | Already repository-relative POSIX; part of portable release identity |

The accepted Runs 013-017 artifacts are not rewritten merely to restyle their historical audit locators. Consumers needing a cross-host policy or family comparison must use the documented portable content identity, not the explicitly platform-local full-package snapshot. A future schema that makes those full snapshots portable would require a separately reviewed migration.

The machine-readable audit is generated by `python scripts/audit_provenance_path_portability.py` under `outputs/provisional/provenance_portability/run_018/`.
